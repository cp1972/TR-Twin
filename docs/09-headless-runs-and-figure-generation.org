* Zweck

Der digitale Zwilling der TR (=tr-twin.html=) ist eine eigenständige Web-App. Ihre
Simulation ist jedoch *reines, deterministisches JavaScript*; der Browser und das DOM
dienen nur der Anzeige. Deshalb lässt sich die App auch *ohne Browser* betreiben
(=headless=), um reproduzierbar Kennzahlen-Zeitreihen und Abbildungen zu erzeugen — etwa
für den Bericht bzw. das Buch.

Diese Datei dokumentiert das Verfahren. Es ist zentral, weil damit jede Abbildung des
Berichts reproduzierbar aus derselben Quelle (der App) hergestellt werden kann.

* Voraussetzungen

- Node.js (getestet mit v22).
- Das Paket =jsdom=: =npm install jsdom= im Arbeitsverzeichnis.
- Die App-Datei =tr-twin.html= und die Theorie-Profile =examples/theories-simul/profil_*.csv=.

* Das Prinzip

Drei Schritte:

1. *Laden.* =jsdom= liest =tr-twin.html= und führt ihr Script aus. Das Script
   initialisiert am Ende automatisch alles (=reset()=, neutraler Referenzzustand, Regler,
   Zeitleiste) und startet die Animationsschleife.
2. *Stubben.* Zwei Browser-Funktionen werden durch Attrappen ersetzt, bevor das Script
   läuft: =canvas.getContext= (es wird nichts gezeichnet) und =requestAnimationFrame=
   (das stoppt die Animationsschleife, sodass die Simulation stillsteht, bis wir sie
   steuern). Optional =matchMedia=.
3. *Steuern.* Wir rufen die App-eigenen Funktionen im Seiten-Kontext auf. Weil die
   zentralen Zustände (=tl=, =S=, Regler …) mit =let= deklariert sind, führen wir den
   Steuercode über ein in die Seite eingefügtes =<script>= aus (nicht von außen).

Determinismus: Der Zufallsgenerator ist =mulberry32= mit =seed = 1=. Gleicher Seed +
gleiches Profil ⇒ *bitidentisches* Ergebnis. Zwei Läufe sind nachweislich identisch.

* Zwei Laufmodi

** Jahr-basierter Durchlauf (=runSeries=)

=runSeries()= spielt die geladene Konfiguration von =tl.start= bis =tl.end= (Vorgabe
1900–2000) Jahr für Jahr durch, setzt dabei die zeitlich interpolierten Reglerkurven des
Profils und sammelt pro Jahr alle Kennzahlen. Ergebnis: eine Zeitreihe mit ~101 Punkten.
Diesen Modus nutzt auch der eingebaute CSV-Export (=exportData=).

** Schritt-basierte Trajektorie

Die Trajektorien-Abbildungen des Berichts (x-Achse = Simulationsschritt, „Neutrales
Szenario, Seed 1, 1819 Schritte") entstehen anders: die Regler werden auf *feste* Werte
gesetzt, dann =reset()=, dann =step(dt)= rund 1819-mal, wobei nach jedem Schritt der
Zustand (=S=, =gini()=, =reciprocity()=, =satS=, =ruler= …) aufgezeichnet wird
(=dt = 1/60*0.68=).

* Profile: wie ein Reglerprofil angewandt wird

Ein Profil-CSV hat als erste Spalte den Regler (Kennung oder französisches Label), danach
je eine Spalte pro Stützjahr; Werte werden linear interpoliert. Die Zuordnung
Label → Regler-Variable ist in der App als =CURSOR_REG= hinterlegt:

| Regler-ID | französisches Label                    | Bedeutung                         |
|-----------+----------------------------------------+-----------------------------------|
| rate      | Circulation des acteurs                | Akteurszirkulation                |
| alpha     | Concentration vers le pôle dominant    | Konzentration zum dominanten Pol  |
| back      | Redistribution interne                 | interne Umverteilung              |
| over      | Perméabilité entre structures          | Permeabilität zwischen Strukturen |
| rho       | Effet miroir                           | Spiegeleffekt                     |
| peak      | Taille idéale                          | ideale Größe (vor Übermacht)      |
| cap       | Essoufflement des dominants            | Erschöpfung der Herrschenden      |
| plast     | Souplesse des parcours                 | Flexibilität der Strecken         |
| mig       | Migration des acteurs                  | Akteursmigration                  |
| decl      | Déclassement des arrivants             | Deklassierung der Neuankömmlinge  |
| dynam     | Avantage aux structures dynamiques     | Vorteil dynamischer Strukturen    |
| anchor    | Poids du nombre                        | Gewicht der Zahl (Bevölkerung)    |

Zeilen mit =chaine_A,C,B,D= legen zusätzlich die strukturelle Kopplung fest.

* Verfügbare Kennzahlen (pro Zeitpunkt)

Aus =runSeries= bzw. dem Schritt-Modus stehen zur Verfügung: =S= (Größen der vier
Strukturen A/B/C/D = Kultur/Politik/Wirtschaft/Medien), =gini= (transversale
Ungleichheit), =reciprocity=, =meanResid= (Überlast/Spannung), pro Struktur =structGini=
und =structRecip= sowie =vertGiniX= (vertikale Ungleichheit), =ruler= (Regentschaft),
=satS= (Satellisierung) und die Akteurskomposition.

* Aufruf

: npm install jsdom
: node run.js  <pfad/zu/tr-twin.html>  <pfad/zu/profil.csv>

Beispielausgabe (Profil Emirbayer):

: Zeitraum: 1900 → 2000 · 101 Jahre
: Start: Jahr 1900: Größen A/B/C/D=0.25/0.24/0.25/0.26  Gini=0.021  Reziprozität=0.972
: Ende:  Jahr 2000: Größen A/B/C/D=0.15/0.55/0.15/0.15  Gini=0.303  Reziprozität=0.472  satS=0.49/0.00/0.49/0.49

Der Startpunkt ist der C4-symmetrische Referenzzustand; am Ende dominiert eine Struktur,
die übrigen sind satellisiert — die erwartete TR-Dynamik.

* Reproduzierbarkeit und Herkunft

Jede erzeugte Abbildung ist damit auf ihren Ursprung zurückführbar: App-Version + Profil +
Seed + Laufmodus (Jahr oder Schritt) + Schrittzahl. Bei unverändertem Profil und Seed ist
das Ergebnis exakt wiederholbar. Der frühere (verlorene) Python-Generator wird auf dieser
Grundlage neu aufgebaut: die Datenextraktion erfolgt headless wie hier beschrieben, das
Rendering übernimmt ein Python-Skript im Report-Stil.
