* Before you start

Since version 68 a run of the twin is prepared in files and not set in the interface. A /run file/ names the mode, the theory profiles or the contract table, the time axis, the seeds and, if wanted, a stimulus. The interface computes the run, shows its results and replays it; the command line (=node run.js=) computes the same run from the same files and writes the same tables and figures. The mechanics of the twin are unchanged: with the same files, v68 computes what v67 computes on its deterministic path (Σ Summary and the headless scripts).

The first part of this document describes the run file, the results and the two ways of computing a run. The second part describes the formats of the files a run file names: theory profiles and contract tables.

Two kinds of input answer different questions and are not interchangeable. A theory profile governs the controls of the twin, and is the form in which a theoretical reading is expressed (/simulation mode/). A contract table supplies individual trajectories and is the appropriate form for biographical or archival material; the cohort then governs the model directly, and the measures are read on the cohort itself (/data mode/). Where a cohort is thin, the caution set out in [[file:05-prism-mode-actor-probes.org][document 5]] applies: it is to be read as a probe rather than as a census.

* The run file

A run file is a CSV with two columns, key and value (further columns where a key takes several values). Lines beginning with =#= are comments. Keys and values are read in English, German or French, without regard to capitals or accents; separators may be commas, semicolons or tabs, and double quotes protect a separator inside a value. Paths are relative to the run file. Examples are in =runs/=.

| Key (en)     | de              | fr          | Value                                                                  | Mode       |
|--------------+-----------------+-------------+------------------------------------------------------------------------+------------|
| mode         | modus           | mode        | =simulation= / =data= (=Simulation=, =Daten=; =simulation=, =données=) | both       |
| profile      | profil          | profil      | a theory profile; one row per theory                                   | simulation |
| steps        | schritte        | pas         | number of steps (default 1819)                                         | simulation |
| start, end   | beginn, ende    | debut, fin  | years: in simulation instead of steps (the profile over its years); in data mode a narrower period | both |
| stimulus     | reiz            | stimulus    | structure, direction, duration, strength, begin: =B,weaken,300,2.6,1819= | simulation |
| free steps   | nachlauf        | pas libres  | free steps after a stimulus (default 6000; 30 000 with M5)             | simulation |
| contracts    | vertragstabelle | contrats    | a contract table                                                       | data       |
| instances    | instanzen       | instances   | a table of mediation and control instances (same format)              | data       |
| probes       | sonden          | sondes      | a small probe extract for the prism mode (instead of =instances=)      | data       |
| categories   | kategorien      | categories  | empty structures: =uniform= (default) / =composition= / =carry=       | data       |
| stepped      | stufen          | paliers     | =yes= (default) / =no=: the cohort in steps or interpolated           | data       |
| trend window | trendfenster    | fenetre     | years per trend period, 1 to 100 (default 10)                          | data       |
| seeds        | startwerte      | graines     | =1-8= or =1,4,7= (default 1–8)                                         | both       |
| output       | ausgabe         | sortie      | folder for the results of =node run.js=                                 | both       |

A structure in a stimulus is written A–D or by name (culture, Kultur, culture …); a direction as strengthen / verstärken / renforcer / + or weaken / schwächen / affaiblir / −. A stimulus run lasts begin + duration + free steps (=steps= is then not used), and is given in steps, not in years. In years (simulation), give both =start= and =end=: every theory runs over the same years. If a line uses semicolons, a comma inside a value is read as a decimal comma (=2,6=).

#+begin_example
# Simulation: Parsons and Luhmann next to the Theory of the Relation
mode,simulation
profile,../simulation-mode/profiles/profil_Parsons.csv
profile,../simulation-mode/profiles/profil_Luhmann.csv
steps,1819
seeds,1-8
#+end_example

#+begin_example
# Datenmodus: die Autobiographien der englischen Arbeiterklasse (Kapitel 11)
modus,Daten
vertragstabelle,../data-mode/topic-models/contracts/N1_lexikon_hiscam_echte_jahre.csv
startwerte,1-8
trendfenster,10
#+end_example

The Theory of the Relation is always computed as the reference: in simulation mode with its default values and all six mechanisms, next to the theories of the run file; in data mode the twin runs with the TR values on the cohort.

* In the interface

- *Run file*: /Choose run file and data…/ — select the run file together with the files it names (multiple selection; they are matched by name). The section shows what the run file asks for, and which files are missing. /▶ Compute/ computes all theories × seeds; /Σ Results/ opens the results.
- *Replay*: after the computation the animation replays one run (selector: theory and seed) with exactly the steps that were computed. /▶ Start/ at the bottom and /Reset/ restart it, /Pause/ holds it, the speed sets the tempo only. Pressing a circle has no effect during a replay, since it would change the run.
- *As a script*: the command for the terminal, the run file to download, and how to install Node.js and jsdom.
- *Downloads*: a report (one HTML file with the run file, all tables and figures), all tables (CSV), and the series (CSV) of every run, to compute one's own trends.
- *For advanced users* (collapsed): the chains, the sliders and the seed of the run being replayed, read-only — they show what can be coded in a profile; the prism probes ([[file:05-prism-mode-actor-probes.org][document 5]]).

Without a run file the twin runs with the TR values, as before.

* The results

** Simulation mode: what do the assumptions of the theories change?

- /Assumptions/: the sliders, chains and mechanisms of each theory next to the TR. A slider a theory does not set is shown as /not assumed · TR value/: the run uses the TR value for it, so the results remain comparable on this point, and the mark says why. A mechanism not assumed does not act. The chains are those the run starts with (path flexibility and M1 may change them).
- /Results/: at the end of the run, median over the seeds, range in brackets, difference to the TR: transversal, horizontal and vertical inequality; reciprocity; sizes; dominant structure (share of seeds); changes of domination (every change of the dominant structure, the dissolution of a domination included; episodes shorter than 300 steps are not counted) and the end of the first domination; satellisation of each structure; changes of regime and the regime at the end (the sequence each structure runs under); takeover of a regime by the satelliser (M2, only for theories that assume it); with a stimulus, the verdict of the stimulus probe per seed (returned, set, still moving), as in the Reizschwelle step of the pipeline.
- /Changes of regime/: for seed 1, when which structure changes its regime, from which to which sequence, and whether by takeover (M2).
- /Figures/: inequalities and reciprocity, sizes, satellisation (theories next to the TR, range as bars), and the trajectories of inequality and reciprocity. A result that exists only under an assumption — the takeover of a regime, which only M2 can produce — is marked /not assumed/ for the theories without it and is not part of the figures. All theories of a run file run equally long (after a stimulus: 30 000 free steps if any theory has M5, which the TR always has).

** Data mode: what does the cohort show over time?

- /Trends/: for each period of the trend window and for the whole period, the change of transversal, horizontal and vertical inequality, reciprocity and the four sizes from the first to the last year, median over the seeds (↑ rises, ↓ falls, → stable). "~" marks a change that does not exceed the spread of the changes between the seeds (with a single seed, nothing is marked). The number of transitions of the contract table per period is given; fewer than five are marked /thin/.
- /Detail per structure/: per structure and period, at the end of the period: size, reciprocity, internal (horizontal) inequality, vertical inequality, satellisation, control capacity, the four instances and the regime.
- /Circulation and mobility/: the transitions between successive coded stages of each actor (control instances excluded; of several stages in the same year, the last one counts, as in the transitions export), per period. /Circulation/ is every movement: same position (a new stage in the same structure and sequence), change of sequence within a structure, change of structure. /Mobility/ is the reading of a transition as ascending, descending or neither, from the change of the actor category at that transition: established > aspirants > conservatives > disappointed (the order the twin uses for vertical inequality). Mobility moves one category at a time; a jump of several categories between two coded stages means that the stages in between are not coded, and counts as that many steps in the same direction. The steps beyond the first are reported as /inferred/, with their share, so that one sees how much of the measured mobility rests on uncoded stages. Transitions without a category in the table are counted as /no category/.
- /Flows between structures/: changes of structure from row to column, per period.
- /Permeability/: per period, the control capacity of the instances of each structure (1 = without control instances), and the migration in the twin: the share of attempted migration that is blocked, and the circulation between structures and between sequences.

HISCAM plays no part in the results of the twin: it is one way, used in chapters 11 and 12 of the book, to classify the material into a contract table.

* On the command line

The same run file computes without a browser:

#+begin_example
node run.js runs/arbeiter_N1.csv --lang de
#+end_example

The results go to =results/<run file>/= (or to the folder of the key =output=, or =--out=): =report.html=, =tables.csv= and one CSV per table in =tables/=, =series.csv=, and the figures in =figures/=. Installation and further headless scripts: [[file:04-headless-runs.org][document 4]].

* Formats of the files

/Population data/ (aggregate demographics: rows = structure × category, columns = years) are no longer offered in the interface since v68; the code is kept, and v67 (branch =main=) still loads them.

** Controller profiles and chain coupling (theory profiles)

A "controller profile" governs the controls over time; named in a run file (key =profile=), it is a theory profile. The format mimics the one with the demographics: first column = control labels (machine identifier or label as an alias), one column per year with control value. Between the years a linear interpolation is applied (held before the first and after the last point). With =steps=, the controls hold the value of the last year; with =start= and =end=, they follow the years. Controls not listed remain at the default value of the digital twin (the TR value). Such a controller profile has been use as a theory profile, providing a comparison between the Theory of the Relation and other theoretical frameworks in sociology. The profile can be edited to support different readings of the same theory or different theories.

Since dialectising two structures is a structural operation (chain coupling, not a control), a profile can also set chains. A row "chain_A,C,B,D" fixes the coupling order of A (here C first). Thus a single profile carries the temporal mechanics (controls) and the structural coupling (chains), enabling a complete theory configuration.

** A note on column names

The column names of the contract table were originally French (=annee=, =categorie=, =poids=) and the files distributed with this repository now use their English equivalents (=year=, =category=, =weight=). The reader accepts both, together with the German forms, so that files written against the earlier convention continue to load. The same holds for the category values: =etabli= and =established=, =decu= and =excluded= are read alike, and a chain row may be written =chain_A= or =chaine_A=.

** Actor cohort and circulation flows

Instead of a macro-demographic curve, a real cohort can be loaded (contract table: actor, dated stages → structure, category). Each actor holds their position from one stage to the next (step function), over their documented career (first to last stage). The sum over the living actors gives, per year, a cohort demographics. In this variant, the cohort /is/ the population: it governs the model directly, and all measures read on the cohort itself. The interpolation proceeds in steps (switch linear/steps; introduced in v44). The macro-demographics remains linear.

Years in which a relational structure has no active actor of the cohort need a category composition all the same, since the model keeps running. Up to v63 the twin set 25 % per category there. Since v64 three treatments are offered (since v68 the run-file key =categories=): uniform (the default, as before), the overall composition of the structure over the whole contract table, or the last observed composition carried forward. Which results rest on gap filling can be seen in the trends: periods with few transitions are marked /thin/. The choice matters for the vertical inequality: in the worked example of the data mode, uniform filling makes the economy appear least stratified, the two other treatments restore it as the most stratified structure (book chapter 12, section 12.9).

*Stimulus protocol (since v65; since v68 the run-file key =stimulus=).* A stimulus is a defined intervention: a structure, a direction (strengthen or weaken), a duration in steps and a strength. /Strengthen/ reinforces the core sequence of the structure. /Weaken/ makes its leading sequence pass its share to the next sequence along the butterfly path of the structure that rules most or gains most power: the weakened structure is reprogrammed around that sequence and runs along its path; weakening further moves the newly set sequence on until the structure runs under the leading structure's core sequence (since v66; without a clear leader the order A→B→C→D→A applies). The weakening never brings a structure back to its own core sequence. A stimulus shows whether the targeted change prevents the return to the state reached without it, not which structure rules. Three switches add the satellisation mechanisms of the theory: /M1/ the chains of a satellised structure align with the order of the satelliser, /M2/ a structure satellised strongly and long enough runs entirely under the satelliser's sequence, /M3/ the satelliser's instances strengthen the same kind of instance in its satellites, the strongest first. Since v66 three more: /M4/ the control instances of a satellised structure strengthen its own core and can be alienated, never completely; /M5/ saturation of domination (Pareto): every further gain costs more, and the dominant is eroded until another structure is stronger (setting /saturation time/); /M6/ force of control (DiMaggio): networked, diversified instances control better. With all of them off the twin computes as before. Since v67 the mechanisms belong to the theory, like the chains: the default configuration (the Theory of the Relation) has all six; a loaded slider profile has only those it declares in a row =mechanismen,M1,M2,…=, otherwise none. For a run file with a stimulus, the twin computes for each theory and seed the run with the stimulus (after =begin= steps, default 1819) and the same run without it, and states whether the run returned, set or is still moving after the free steps (6000; 30 000 with M5, since exhaustion takes longer) — the verdict of the stimulus probe of v65–v67.

A second element shows the circulation flows (introduced incrementally from version v45 to version v46): a 4×4 matrix (row = origin structure, column = target structure) counts the structure switches of the actors in a sliding window around the current year and so makes visible which paths the actors carry and how the circulation regime shifts over time. Important caution: the cohort is thin (in the test case 6–14 active actors) — it is to be read as a probe, not as a census (see [[file:05-prism-mode-actor-probes.org][document 5]]).

The contract table has carried, since v50, an additional column "sequence" (sequence stake per stage, A/B/C/D; default = the identity sequence of the structure). Each actor is thus described by a triple layer (relational structure, sequence, category). This layer is kept descriptive. It does not govern the living model, but appears in the actor file, in the sequence transitions of the export, and in an aggregated figure (see [[file:05-prism-mode-actor-probes.org][document 5]]).

* What-if scenarios

The scenario panel of v62–v67 (trend × transformation × horizon) is not offered in the interface since v68: the trends of a data run take its place as a reading of the loaded history. The code is kept, and v67 (branch =main=) still offers the panel.
